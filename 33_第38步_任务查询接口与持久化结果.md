### 3.1 report_outcome 为什么要加

原来run_deep_agent一拿到答案就广播task_result；现在API必须先写任务账本再广播，因此API传 `report_outcome=False`。直接运行第09或第21步示例仍不传这个参数，默认True，保留原来的终态通知行为。

星号 `*` 使后面的参数必须用名字传：`report_outcome=False`。前面的task_query是用户问题，session_id仍是会话编号，不把它换成task_id，否则多轮对话会被拆散。

### 3.2 登记册由谁创建、何时恢复

HTTP任务由execute_task先创建登记册，run_deep_agent发现已经有就直接使用；独立命令行没有外层API时，run_deep_agent才创建一册，并记录evidence_token。finally只恢复自己创建的那册，不能替外层提前清掉。

`append_source_references(final_answer)` 在父图执行结束且存在正文后调用。图里的父子助手通过工具收集到的S1/F1会出现在答案附录；它不是从模型输出里猜URL，更不是把所有历史会话来源混在一起。

异常与取消仍向上抛。report_outcome=False时，主任务不广播终态，由API负责持久化和通知；finally仍恢复会话Token，异常不会把A的目录带进B。

def session_folder(root: Path, thread_id: uuid.UUID) -> Path:

def safe_output_file(thread_id: uuid.UUID, filename: str) -> Path:
    base = session_folder(output_root, thread_id).resolve()
    relative = Path(filename)
    if not filename or relative.is_absolute():
        raise HTTPException(400, "文件名无效")
    target = (base / relative).resolve()
    if target == base or not target.is_relative_to(base):
        raise HTTPException(400, "文件路径越界")
    return target

@asynccontextmanager
async def lifespan(app: FastAPI):
    manager.set_loop(asyncio.get_running_loop())
    monitor.set_websocket_manager(manager)
    try:
        async with agent_runtime():
            try:
                yield
            finally:
                for task in list(running_tasks):
                    task.cancel()
                if running_tasks:
                    await asyncio.gather(*running_tasks, return_exceptions=True)
    finally:
        monitor.set_websocket_manager(None)
        manager.loop = None

@app.websocket("/ws/{thread_id}")

    key = str(thread_id)
    await manager.connect(websocket, key)
    try:
        while True:
            message = await websocket.receive_text()
            if message == "ping":
                await websocket.send_json({"type": "pong"})
    except WebSocketDisconnect:
        pass
    finally:
        manager.disconnect(websocket, key)

@app.post("/api/upload")
async def upload_file(
    thread_id: uuid.UUID = Form(...),
    file: UploadFile = File(...),
) -> dict:
    raw_name = file.filename or ""
    if (
        not raw_name or raw_name in {".", ".."}
        or "/" in raw_name or "\\" in raw_name
    ):
        raise HTTPException(400, "只接受单个文件名")

    folder = session_folder(upload_root, thread_id)
    folder.mkdir(parents=True, exist_ok=True)
    target = folder / raw_name
    temporary = None
    size = 0
    try:
        with NamedTemporaryFile(
            mode="wb", dir=folder, prefix=".upload-", delete=False
        ) as output:
            temporary = Path(output.name)
            while chunk := await file.read(1024 * 1024):
                size += len(chunk)
                if size > MAX_UPLOAD_BYTES:
                    raise HTTPException(413, "文件超过 10 MB")
                output.write(chunk)
        os.replace(temporary, target)
    except BaseException:
        if temporary is not None:
            temporary.unlink(missing_ok=True)
        raise
    finally:
        await file.close()
    return {"status": "uploaded", "filename": raw_name}


@app.get("/api/files")
async def list_files(thread_id: uuid.UUID) -> dict:
    folder = session_folder(output_root, thread_id).resolve()
    if not folder.exists():
        return {"files": []}
    files = []
    for path in folder.rglob("*"):
        if path.is_file() and path.resolve().is_relative_to(folder):
            files.append({
                "name": str(path.relative_to(folder)),
                "size": path.stat().st_size,
            })
    return {"files": files}

## 5. 新的请求与响应怎么读

请求体示意：

```json
{
  "query": "请读取我上传的资料",
  "thread_id": "会话的UUID",
  "task_id": "本次请求的UUID"
}
```

以上两个UUID中文值是示意，不是能直接提交的真实UUID。第39步浏览器用crypto.randomUUID生成。旧脚本没有task_id也能提交，服务会生成并返回；新页面提前生成并保存编号，才有机会在提交回执丢失时找回。

`Field(min_length=1,max_length=20000)` 校验字符串长度，之后strip再拦截纯空白。thread_id和task_id通过Pydantic按UUID校验，无效请求返回422，不进入模型。

| 接口 | 具体职责 |
| --- | --- |
| POST `/api/task` | 先create落库；新任务安排execute_task；相同编号原样请求复用记录；返回202表示受理，不等于完成 |
| GET `/api/tasks?thread_id=...` | 查询该会话最近20条任务，用于恢复问题、状态、答案与来源 |
| GET `/api/tasks/{task_id}?thread_id=...` | 按任务和会话精确查询；编号不匹配时404 |

同task_id换问题或同会话已有活跃任务返回409；不要在前端收到409后偷偷换编号无限重试。

## 6. execute_task 一次完整执行

| 局部变量/Token | 具体保存什么 | 谁使用 |
| --- | --- | --- |
| registry | 这次T1的EvidenceRegistry对象 | 子助手、工具、答案/报告、任务结束保存来源 |
| evidence_token | 写入登记册前的上下文状态 | finally恢复 |
| task_token | 写入T1前的状态 | monitor事件读到T1，finally恢复 |
| thread_token | 写入A前的状态 | monitor按A找WebSocket |
| session_token | 写入A目录前的状态 | 即使主任务准备阶段失败，外层通知仍有会话环境 |
| answer | 主任务返回的含来源最终字符串 | 写入账本，再广播 |

```text
create(T1,A,问题)提交成功
→ create_task安排后台执行，不创建新操作系统线程
→ execute_task写入本次上下文
→ to_thread(mark_running)把同步SQLite工作放到线程池
→ await run_deep_agent(...,report_outcome=False)
→ 工具记录来源、生成报告、主图返回答案
→ to_thread(finish,succeeded)保存答案和来源
→ report_sources + report_task_result
→ finally恢复上下文
```

`asyncio.to_thread` 用来处理同步SQLite调用，`await` 等待提交完毕再发完成通知。它与模型子助手不是同一个概念。running_tasks集合仍只跟踪当前进程中的协程任务，数据库账本才用于重启后查询。

内层try只围住模型执行，except分别处理失败与取消；else只在模型执行正常返回后保存成功结果。把数据库提交放在else，是避免提交阶段的错误或取消被错误归类成模型失败。已开始的SQLite线程事务仍可能完成，所以即使提交时等待被取消、没有发出完成通知，之后仍应查询账本确认实际状态。

异常路径会写failed与异常类型；取消路径会写cancelled再重新抛CancelledError。通知发送失败不会删除已经提交的数据库记录。没有WebSocket连接时，monitor可能打印“没有连接”，任务依然能成功落库。

## 7. lifespan：服务开门与关门分别做什么

启动时先initialize任务表、recover_interrupted标记遗留任务，再设置WebSocket循环并进入agent_runtime。数据库连接仍由agent_runtime按前面教程管理。

运行到yield后，FastAPI开始处理请求。关闭时回到yield后，取消并等待running_tasks，这让execute_task有机会记录cancelled；然后退出agent_runtime关闭检查点连接，最后清掉manager.loop。

tasks.db保存的是任务结果，不负责让异步协程“永生”。单进程是本版本的明确运行约定。
