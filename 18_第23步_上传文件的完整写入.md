# 第 23 步：上传半途失败时，不要毁掉旧文件

## 本步要解决的问题

第 13 步的上传接口直接以 `"wb"` 打开最终文件名。若 A 之前上传过“合同.txt”，再次上传同名文件却在 10 MB 限制处失败，旧文件可能已经被截断，异常清理还会把它删掉。本步改成“先写临时文件，完整收齐后再替换正式文件”。

具体例子：A 已有“合同.txt”内容为 `旧版`。新上传的数据超过限制，接口返回 413；再次读取“合同.txt”应仍是 `旧版`。若新上传完全成功，才把它替换成新版。这是文件写入顺序的练习，不需要调用大模型。

## 文件与依赖

- **修改 learning/api/server.py → upload_file()**：把“直接写最终路径”换成“写同目录临时文件 → 检查大小 → `os.replace`”。同文件的 `session_folder`、`safe_output_file` 和其他路由保持原样。
- **新建 learning/examples/23_atomic_upload.py**：直接调用正式上传函数，模拟同名旧文件与超限新文件。实验入口只放 `examples/`。
- **依赖**：新增的 `os`、`tempfile.NamedTemporaryFile` 是标准库；`UploadFile` 和 `HTTPException` 已来自 FastAPI；`requirements.txt` 无须改。外层目录用 `learning/.venv/bin/python -c 'from tempfile import NamedTemporaryFile; print("标准库可用")'` 检查解释器。
- `learning/updated/session_…/` 仍是收件箱；`learning/output/session_…/` 仍是任务工作台。本步只改变上传完成前的存放方式，不会自动把文件导入 RAGFlow。

## 1. 在 learning/api/server.py 增加导入和常量

文件顶部现有导入附近增加：

~~~python
import os
from tempfile import NamedTemporaryFile
~~~

在 `upload_root`、`output_root` 等模块级路径变量之后加：

~~~python
MAX_UPLOAD_BYTES = 10 * 1024 * 1024
~~~

这个名字明确单位是**字节**；10 MB 是本教程的单文件上限。把它放在函数外，练习脚本才能临时改成 4 字节，用很小的数据复现超限，不必真的创建 10 MB 文件。

## 2. 替换 learning/api/server.py → upload_file() 的写入部分

原函数从 `raw_name = file.filename or ""` 到路径验证保持不变。找到 **learning/api/server.py → upload_file()** 中从 `folder = session_folder(...)` 到函数末尾的这段**替换前（旧代码）**：

~~~python
    folder = session_folder(upload_root, thread_id)
    folder.mkdir(parents=True, exist_ok=True)
    target = folder / raw_name
    size = 0
    try:
        with target.open("wb") as output:
            while chunk := await file.read(1024 * 1024):
                size += len(chunk)
                if size > 10 * 1024 * 1024:
                    raise HTTPException(413, "文件超过 10 MB")
                output.write(chunk)
    except Exception:
        target.unlink(missing_ok=True)
        raise
    finally:
        await file.close()
    return {"status": "uploaded", "filename": raw_name}
~~~

把上面整段换成以下**替换后（新代码）**；不要连同前面的文件名检查一起删掉：

~~~python
    folder = session_folder(upload_root, thread_id)
    folder.mkdir(parents=True, exist_ok=True)
    target = folder / raw_name
    temporary = None
    size = 0
    try:
        with NamedTemporaryFile(
            mode="wb", dir=folder, prefix=".upload-", delete=False
        ) as output:
            temporary = Path(output.name)
            while chunk := await file.read(1024 * 1024):
                size += len(chunk)
                if size > MAX_UPLOAD_BYTES:
                    raise HTTPException(413, "文件超过 10 MB")
                output.write(chunk)
        os.replace(temporary, target)
    except BaseException:
        if temporary is not None:
            temporary.unlink(missing_ok=True)
        raise
    finally:
        await file.close()
    return {"status": "uploaded", "filename": raw_name}
~~~

对照看：旧代码用 `target.open("wb")` 直接写正式文件，失败时还会 `target.unlink()`；新代码先写 `temporary`，完整收齐才用 `os.replace(temporary, target)` 接班，失败时只删除本次临时文件。两个版本最后都关闭 `file` 并返回上传结果。

`target` 是正式文件路径，`temporary` 是同一会话目录中随机命名的临时文件；`output` 是打开的写入对象。先检查累计 `size`，再写当前 `chunk`。全部读完并正常关闭 `output` 后，`os.replace` 才把临时文件换成正式文件；它们在同一目录，避免跨文件系统移动问题。若超限，`raise HTTPException(413, ...)` 跳到 `except BaseException`，只删除**这次创建的临时文件**，旧 `target` 不受影响。这里捕获 `BaseException` 是为了连异步任务取消也能清理临时文件，清理后立刻 `raise`，绝不把取消当成功。`finally` 关闭上传流。

`os.replace` 返回 `None`；上传函数最后返回的字典表示服务端完整收下并替换文件，**不表示** Agent 已复制或读取它。相同名称的成功上传会覆盖旧版本；若需要版本历史，需要另一步设计。

| 变量 | 上传开始 | 超限时 | 成功时 |
| --- | --- | --- | --- |
| `target` | 指向“合同.txt”正式路径 | 仍保存旧版 | 被替换成新版 |
| `temporary` | `None` → 随机临时路径 | 删除 | 被 `os.replace` 移走 |
| `size` | 0 | 超过限制时抛 413 | 最终上传字节数 |
| `file` | FastAPI 提供的上传对象 | `finally` 关闭 | `finally` 关闭 |

## 3. 新建 learning/examples/23_atomic_upload.py

~~~python
import asyncio
import sys
import uuid
from io import BytesIO
from pathlib import Path
from tempfile import TemporaryDirectory
from unittest.mock import patch

sys.path.insert(0, str(Path(__file__).resolve().parent.parent))
from fastapi import HTTPException, UploadFile
import api.server as server


async def main():
    thread_id = uuid.uuid4()
    with TemporaryDirectory() as directory:
        with patch.object(server, "upload_root", Path(directory)):
            with patch.object(server, "MAX_UPLOAD_BYTES", 4):
                old = UploadFile(file=BytesIO(b"old"), filename="contract.txt")
                await server.upload_file(thread_id, old)
                target = server.session_folder(Path(directory), thread_id) / "contract.txt"
                assert target.read_bytes() == b"old"

                too_large = UploadFile(file=BytesIO(b"12345"), filename="contract.txt")
                try:
                    await server.upload_file(thread_id, too_large)
                except HTTPException as exc:
                    assert exc.status_code == 413
                else:
                    raise AssertionError("超限上传应被拒绝")

                assert target.read_bytes() == b"old"
                assert not list(target.parent.glob(".upload-*"))

                replacement = UploadFile(file=BytesIO(b"new"), filename="contract.txt")
                result = await server.upload_file(thread_id, replacement)
                assert result == {"status": "uploaded", "filename": "contract.txt"}
                assert target.read_bytes() == b"new"
                assert not list(target.parent.glob(".upload-*"))

                cancelled = UploadFile(file=BytesIO(b"unused"), filename="contract.txt")
                with patch.object(
                    cancelled, "read", side_effect=[b"x", asyncio.CancelledError()]
                ):
                    try:
                        await server.upload_file(thread_id, cancelled)
                    except asyncio.CancelledError:
                        pass
                    else:
                        raise AssertionError("取消应向上抛出")
                assert target.read_bytes() == b"new"
                assert not list(target.parent.glob(".upload-*"))
                print("超限和取消后旧文件保留、临时文件已清理；成功后新文件接班")


asyncio.run(main())
~~~

从外层目录运行 `learning/.venv/bin/python learning/examples/23_atomic_upload.py`。这直接测试正式函数的三条路径：超限时保留旧版并清理临时文件、完整上传后替换成新版、读取中取消时保留新版并清理临时文件。`patch.object(cancelled, "read", ...)` 只在这一小段实验里让第二次读取抛出取消；HTTP 表单解析已经在第 13 步验证过。理解检查：为什么 `os.replace` 一定要放在读取循环结束**之后**？
